파비콘은 여러 이미지 형식으로 저장할 수 있습니다. 형식마다 장점이 있으며, 두세 가지를 조합하는 것이 가장 좋은 구성입니다.

## ICO

최초의 파비콘 형식입니다. `.ico` 파일은 16×16, 32×32, 48×48처럼 서로 다른 크기의 비트맵 여러 개를 담을 수 있는 컨테이너여서, 운영체제가 알맞은 것을 고를 수 있습니다.

- **장점:** 지금까지 나온 모든 브라우저에서 지원됩니다. `/favicon.ico`로 자동 요청됩니다. 파일 하나로 여러 크기를 제공합니다.
- **단점:** 파일 크기가 큽니다. 벡터처럼 확대·축소할 수 없습니다. 만들려면 전용 도구가 필요합니다.

**이럴 때 사용하세요:** 주로 호환성을 위해 사이트 루트에 `favicon.ico` 하나를 두는 용도.

## PNG

PNG는 오늘날 파비콘에 가장 많이 쓰이는 형식입니다. 투명도를 지원하고 압축 효율도 좋습니다.

- **장점:** 어디서나 지원됩니다. 어떤 디자인 도구에서든 쉽게 내보낼 수 있습니다. 180×180 `apple-touch-icon`과 192×192, 512×512 매니페스트 아이콘에 적합합니다.
- **단점:** 크기마다 별도의 파일이 필요합니다. 원래 픽셀 크기 이상으로는 선명하게 확대되지 않습니다.

**이럴 때 사용하세요:** 터치 아이콘, 매니페스트 아이콘, 그리고 SVG를 지원하지 않는 브라우저를 위한 대체 아이콘.

## SVG

SVG는 벡터 형식이므로, 작은 파일 하나로 모든 크기와 모든 화면 밀도에서 선명하게 표시됩니다.

- **장점:** 어디서나 완벽하게 선명합니다. 파일 크기가 아주 작습니다. CSS 미디어 쿼리로 다크 모드에 반응할 수 있습니다.
- **단점:** 아직 모든 브라우저가 지원하지는 않으므로 ICO 또는 PNG 대체 아이콘을 함께 두세요. 디테일이 많은 로고는 16×16용으로 단순화한 버전이 여전히 필요할 수 있습니다.

SVG 파비콘은 사용자가 어두운 테마를 선호할 때 색상을 바꿀 수 있습니다.

```xml
<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 32 32">
  <style>
    path { fill: #0f172a; }
    @media (prefers-color-scheme: dark) { path { fill: #f8fafc; } }
  </style>
  <path d="M4 4h24v24H4z"/>
</svg>
```

## GIF, JPEG, WebP

이 형식들은 대부분의 최신 브라우저에서 작동하지만, 아이콘으로서의 장점은 거의 없습니다. GIF는 애니메이션을 지원하지만, 움직이는 파비콘은 산만하고 모든 곳에서 표시되지도 않습니다. JPEG는 투명도를 지원하지 않습니다. WebP와 AVIF는 효율적이지만, 파비콘을 읽는 모든 플랫폼에서 지원되지는 않습니다.

## 어떤 형식을 사용해야 할까요?

현재 가장 안정적인 조합은 다음과 같습니다.

```html
<link rel="icon" href="/favicon.ico" sizes="32x32">
<link rel="icon" href="/icon.svg" type="image/svg+xml">
<link rel="apple-touch-icon" href="/apple-touch-icon.png">
<link rel="manifest" href="/manifest.webmanifest">
```

SVG를 이해하는 브라우저는 `icon.svg`를 사용하고, 그렇지 않은 브라우저는 `favicon.ico`로 대체합니다.

## Favicon.is는 어떤 형식을 반환하나요?

Favicon.is는 웹사이트가 제공하는 형식 그대로 아이콘을 반환합니다. 대부분은 PNG이지만 ICO, SVG, JPEG, GIF 또는 WebP일 수도 있습니다. 어떤 형식을 받았는지는 `Content-Type` 응답 헤더에서 항상 확인할 수 있으며, 모든 형식은 일반 `<img>` 태그에서 작동합니다.
