ファビコンは、いくつかの画像形式で保存できます。それぞれに長所があり、2〜3種類を組み合わせるのが最適な構成です。

## ICO

最初のファビコン形式です。`.ico` ファイルは、16×16、32×32、48×48など異なるサイズの複数のビットマップを格納できるコンテナで、OSが適切なものを選べるようになっています。

- **長所**：これまでに作られたすべてのブラウザが対応。`/favicon.ico` で自動的にリクエストされる。1つのファイルで複数のサイズをまかなえる。
- **短所**：ファイルサイズが大きい。ベクターのような拡大縮小はできない。作成に専用のツールが必要。

**用途**：主に互換性のために、サイトのルートに `favicon.ico` を1つ置く。

## PNG

PNGは、現在ファビコンで最も一般的な形式です。透過に対応し、圧縮効率にも優れています。

- **長所**：あらゆる環境で対応。どのデザインツールからも簡単に書き出せる。180×180の `apple-touch-icon` や、192×192と512×512のマニフェストアイコンに最適。
- **短所**：サイズごとに別ファイルが必要。ピクセルサイズを超えて拡大すると鮮明さを保てない。

**用途**：タッチアイコン、マニフェストアイコン、SVGに対応していないブラウザ向けのフォールバック。

## SVG

SVGはベクター形式なので、小さなファイル1つで、どのサイズ・どの画面密度でも鮮明に表示されます。

- **長所**：どこでも完璧にくっきり表示。ファイルサイズがごく小さい。CSSのメディアクエリでダークモードに反応できる。
- **短所**：ブラウザの対応がまだ完全ではないため、ICOまたはPNGのフォールバックが必要。細部の多いロゴは、16×16用に簡略化したバージョンが必要な場合もある。

SVGファビコンは、ユーザーがダークテーマを好む場合に色を切り替えられます。

```xml
<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 32 32">
  <style>
    path { fill: #0f172a; }
    @media (prefers-color-scheme: dark) { path { fill: #f8fafc; } }
  </style>
  <path d="M4 4h24v24H4z"/>
</svg>
```

## GIF、JPEG、WebP

これらの形式はほとんどのモダンブラウザで使えますが、アイコンとしての利点はあまりありません。GIFはアニメーションに対応していますが、アニメーションするファビコンは気が散るうえ、どこでも表示されるわけではありません。JPEGは透過に対応していません。WebPとAVIFは効率的ですが、ファビコンを読み込むすべてのプラットフォームが対応しているわけではありません。

## どの形式を使うべきか

現在最も信頼できる組み合わせは次のとおりです。

```html
<link rel="icon" href="/favicon.ico" sizes="32x32">
<link rel="icon" href="/icon.svg" type="image/svg+xml">
<link rel="apple-touch-icon" href="/apple-touch-icon.png">
<link rel="manifest" href="/manifest.webmanifest">
```

SVGを解釈できるブラウザは `icon.svg` を使い、それ以外のブラウザは `favicon.ico` にフォールバックします。

## Favicon.isが返す形式

Favicon.isは、Webサイトが提供している形式のままアイコンを返します。多くの場合はPNGですが、ICO、SVG、JPEG、GIF、WebPのこともあります。どの形式を受け取ったかは `Content-Type` レスポンスヘッダーで必ず確認でき、どの形式も通常の `<img>` タグで問題なく表示できます。
